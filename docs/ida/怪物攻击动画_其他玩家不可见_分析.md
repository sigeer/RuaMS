# 其他玩家看不到怪物攻击动画（MOVE_MONSTER activity 被改写为 -1）

> IDA 数据库：`` `Angel.i64 ``（v83，基址 0x400000）
> 相关代码：`src/Application.Core/Channel/Net/Handlers/MoveLifeHandler.cs`、`src/Application.Core/Game/Life/Monster.cs`
> 关联提交：`cbdb00edd`（重构：mob buff）

---

## 1. 现象

玩家 A 攻击怪物后：

* 玩家 B 能看到 A 的**受击动画**（每次都有）；
* 玩家 B 只能看到怪物**第一次**攻击的动画，之后怪物的攻击动画只有 A 自己能看见。

因为 A 是怪物 controller，服务端广播移动包时会跳过 controller（见 `AbstractAnimatedMapObject.BroadcastMovement`），
所以“只有 A 看得见”= 服务端后来广播出去的移动包里已经不含攻击动作了。

---

## 2. 结论（根因）

`Monster.canUseAttack` 中的攻击冷却判断写反，导致第一次攻击之后该攻击永远被判为不可用：

```csharp
// 修复前（错误）
if (usedAttacks.TryGetValue(attackPos, out var cd) && cd < now)
{
    return -1;
}
```

`usedAttacks[attackPos]` 存的是**冷却结束时间**，语义应为“还没到结束时间（`cd > now`）才拒绝”。
写成 `cd < now` 后：

1. 第一次攻击：字典里没有记录 → 返回 1，`usedAttacks[attackPos] = now + attackAfter`；
2. 过了 `attackAfter` 毫秒后：`cd < now` 成立 → 返回 -1；
3. 返回 -1 的路径**不会刷新**字典，于是之后每次都是 -1（永久失效，怪物不死/不重置 buff 就不会恢复）。

`MoveLifeHandler` 收到 -1 后会把移动包里的 activity 改写成 -1：

```csharp
int atkStatus = monster.canUseAttack(castPos, now, isSkill);
if (atkStatus < 1)
{
    rawActivity = -1;   // ← 广播出去的 MOVE_MONSTER 不再带攻击动作
    pOption = 0;
}
```

客户端收到 activity = -1（字节 0xFF）就直接跳过整段动作处理，于是**除 controller 外的玩家都看不到怪物攻击动画**。
受击动画走的是另一个包（DAMAGE_PLAYER 0xC0），不受影响，所以 B 仍然看得到 A 被击中的表现。

`canUseSkill` 有同样的反向判断（`cd < now`）：怪物技能在冷却期内反而可以放，冷却结束后却永远放不出来。

## 3. 客户端证据（IDA）

### 3.1 `CMob::OnMove`（0x66BE61）——移动包里的 activity 就是怪物动画的来源

```c
v45 = <包里的 activity 字节>;
if ( (v45 & 0x80) == 0 )            // ← 最高位置位就整段跳过
{
    v41 = v45 & 1;                  // 方向
    v15 = v45 >> 1;                 // action = activity / 2
    ...
    if ( v15 < 12 || v15 > 20 )     // 12..20：攻击
    {
        if ( v15 < 6 || v15 > 8 ) { if ( v15 >= 21 && v15 <= 37 ) { ...技能动画/特效... } }
        else { ActionDelay = CMob::GetActionDelay(this, v15); ... }
    }
    else
    {
        CMob::DoAttack(this, v21, v20, v41, v42);   // ← 怪物攻击动画
    }
}
```

* 服务端 activity 取值范围与此一致：攻击 `24..41`（→ action 12..20）、技能 `42..59`（→ action 21..29）；
* `MoveLifeHandler` 广播前做 `rawActivity & 0x7F`（清最高位），正常包不受影响；
* activity = -1 时写入的字节是 `0xFF`，最高位为 1 → 动画、音效（`sub_989BA1`）、技能特效全部跳过。

### 3.2 `CUserRemote::OnHit`（0x9832E3，opcode 0xC0）——只负责“别人被击中”

解码顺序（与 `PacketCreator.DamagePlayer` 完全对应）：

```
[1] attackIndex   [4] damage
if (attackIndex >= -1) { [4] mobId  [1] direction }
[1] pgmr
if (pgmr) { [1] is_pg  [4] oid  [1] action  [2] posX  [2] posY }
[1] stance
[4] finalDamage
if (finalDamage == -1) [4] fake
```

* `attackIndex <= -2` 直接跳到 `finalDamage`，不读怪物字段；
* 受击动画/掉血表现无论如何都会执行（`MakeIncDecHPEffect`）；
* 与怪物动画相关的那段（`CMobTemplate::GetMobTemplate` → `GetAttackInfo(attackIndex)` →
  `CAnimationDisplayer::Effect_General` + `sub_989BA1`）**只在 `attackIndex >= 0` 时才走**，
  且依赖 mob 模板/攻击信息，属于“攻击特效/音效”，不是怪物本体的动画。

结论：B 看不到怪物本体动画，问题不在 DAMAGE_PLAYER 包，而在 MOVE_MONSTER 的 activity。

## 4. 修复

`src/Application.Core/Game/Life/Monster.cs`：

1. `canUseAttack`：去掉基于冷却的拒绝（与重构前、以及 BeiDou 参考实现一致，那里这块判断是注释掉的），
   只保留“攻击信息不存在 / MP 不够”两种拒绝；`usedAttacks` 仍记录冷却结束时间以备后用。
   若将来要真正限制攻击频率，应写成 `cd > now`，但需注意冷却期内到达的攻击包其动画同样不会广播给其他人。
2. `canUseSkill`：`cd < now` → `cd > now`（恢复重构前的 `usedSkills.Contains(...)` 语义）。

`src/Application.Core/Channel/Net/Handlers/TakeDamageHandler.cs`：
广播受击包恢复为 IDA 对照过的 `PacketCreator.DamagePlayer(...)`（见 3.2，两者字段一一对应；
调试期间改成 `damagePlayer(...)` 的写法把 `oid`/`action` 传反了——`oid` 位置传了常量 6，
客户端会因此找不到怪物，反击动画无法播放）。

验证：`dotnet build ./src/Application.Host/Application.Host.csproj` → 0 错误。

## 5. 游戏内验证方法

两人同图，B 站在能看见怪的位置：

1. A 攻击怪物，让怪物连续攻击 A；
2. B 应能看到怪物**每一次**攻击动作（而不只是第一次）；
3. 顺带确认：怪物技能在冷却结束后仍能正常释放（`canUseSkill` 的修复）。

若仍有偶发收不到动画的攻击，可进一步把 `MoveLifeHandler` 中 `rawActivity = -1` 的分支也去掉，
让服务端无条件转发客户端上报的动作（服务端不再改写 activity，动画与 controller 本地表现完全一致）。
