# 多语言消息（i18n）

本文说明服务端文本资源的存放方式、加载逻辑和修改流程。原先的 `.resx` 已全部迁移到 JSON。

关联：`docs/ida/CTextAnalyzer_文本换行_分析.md`（客户端换行判定依据）。

## 1. 为什么不是 resx

客户端 `CTextAnalyzer::AnalyzeText`（`0x99DD54`）**只把 `0x0D`（CR）当换行**，`0x0A`（LF）是普通字符，
`0x5C`（`\`）与 CR 走同一分支（证据见 `docs/ida/CTextAnalyzer_文本换行_分析.md`）。

resx 的值是 XML 文本原样，`GenerateResource` 不做 C# 字符串转义，所以：

- 值里写**字面量** `\r\n` → 编译成 `5C 72 5C 6E`，靠客户端反斜杠分支"碰巧"能换行；
- 值里写**物理换行** → 编译成文件里真实的字节，而仓库 `.gitattributes` 是 `* text=auto eol=lf`，
  提交进 git 的是**裸 `0A`**，客户端不会换行。

第 2 种就是 `ScriptTalk.PartyQuest_Requirement` 等 5 个键"换行丢失"的根因。

JSON 没有这个问题：文件里写 `"\r\n"`，解析后就是真实 `0D 0A`，与 git 怎么存盘、编辑器怎么保存无关。
所以**规则是：值里需要换行时，一律写成 JSON 转义 `\r\n`，不要写物理换行。**

## 2. 文件布局

### 宿主

```
src/Application.Resources/i18n/
├── ClientMessage/          # 玩家可见消息（含组队任务的通用提示）
│   ├── zh-CN.json
│   └── en-US.json
├── MessageCategories.cs
└── MessageStore.cs

src/Application.Plugin.Script/i18n/
└── ScriptMessage/          # NPC / 事件脚本消息
    ├── zh-CN.json
    └── en-US.json
```

### 插件

一个插件就是一个目录，**DLL、私有依赖、文案都放在一起**：

```
Plugins/
└── Application.Plugin.TreasureMap/
    ├── Application.Plugin.TreasureMap.dll
    └── i18n/
        └── TreasureMapText/
            ├── zh-CN.json
            └── en-US.json
```

> 注意 `i18n/` 与 DLL **同级**，不在类别名那一层重复插件名。每个插件独占自己的整棵目录，
> 因此两个插件都叫 `SomeText` 也不会冲突——加载顺序上先注册的生效，后者会打一条 Warning。

源码侧的对应结构是 `src/Application.Plugin.TreasureMap/i18n/TreasureMapText/*.json`，
插件构建时按同样的相对路径拷进 `Plugins/{插件名}/`。

约定：

- **类别目录名 == 生成的常量类名**（`ClientMessage`、`ScriptMessage`、`TreasureMapText`）；
- **文件名 == `CultureInfo.Name`**（`zh-CN.json`、`en-US.json`）；
- JSON 是扁平对象 `{ "Key": "value" }`，UTF-8 无 BOM，2 空格缩进。

`ClientMessage` 是原 `ClientMessage` + `SystemMessage` 合并而来（键互不冲突）；
`ScriptMessage` 是原 `ScriptTalk`。

## 3. 编译期键检查

`tools/Message.SourceGenerator` 读取所有 `i18n/{Category}/*.json`，为每个类别生成：

```csharp
public static partial class ClientMessage
{
    public const string Ban_NoticePlayer = "Ban_NoticePlayer";
    // ...
}
```

因此：

- `nameof(ClientMessage.Ban_NoticePlayer)` 和 `ClientMessage.Ban_NoticePlayer` 都等于 `"Ban_NoticePlayer"`；
- 键写错是**编译错误**，不会等到运行期才发现；
- 常量值恒等于键名，**消息的键就是 JSON 里的键**。

非法的 C# 标识符（例如带空格或标点的键）会被跳过并报 `MSG001`（Info）；
与生成成员同名（`Get`/`Format`/`GetDefault`/`FormatDefault`）的键报 `MSG002`（Error）。

需要在**插件里**加文案时，照抄这两行即可（`MessageSource.props` 只负责把 JSON 交给生成器并随编译输出）：

```xml
<ProjectReference Include="..\..\tools\Message.SourceGenerator\Message.SourceGenerator.csproj"
                  OutputItemType="Analyzer" ReferenceOutputAssembly="false" />
<Import Project="..\..\tools\Message.SourceGenerator\MessageSource.props" />
```

## 4. 加载与热重载

`MessageStore` 只读磁盘，**不使用内嵌资源**。搜索目录分两类：

| 来源 | 目录 | 注册方式 |
|------|------|---------|
| 宿主 | `AppContext.BaseDirectory/i18n` | 两个宿主启动时各调一次 `MessageStore.Initialize()` |
| 插件 | `Plugins/{插件名}/i18n` | `PluginContainer` 构造时 `AddDirectory`，卸载时 `RemoveDirectory` |

- **优先级**：宿主根目录在前，插件目录按注册顺序在后，**首个命中的文件生效**；
- **语言回退**：目标语言 → `zh-CN` → `null`；
- **缓存**：按 `(类别, 语言)` 缓存解析结果；插件目录的引用计数归零时清空缓存；
- **热重载**：`MessageStore.Initialize()` 会启动 `FileSystemWatcher`（递归监听 `*.json`），
  改动文件后对应条目失效并重新读取，**不用重启服务**。解析失败时保留旧缓存并记警告日志；
- **未调用 `Initialize()`** 时没有任何搜索目录，`Get` 一律返回 `null`（单元测试因此必须显式初始化）；
- 增加/移除目录、改动类别归属都会清空缓存：插件热重载时新旧容器会短暂共享同一个目录，
  所以 `AddDirectory`/`RemoveDirectory` 按**引用计数**处理，旧容器卸载不会摘掉新容器还在用的目录。

两个宿主的入口：

```csharp
MessageStore.Initialize();   // src/Application.Host/Program.cs、src/Application.Host.Channel/Program.cs
```

## 5. 修改流程

**改文案**：直接改 JSON，重启或等热重载生效。

**加一个键**：在**所有语言**的同类别 JSON 里加上同名键。只加一种语言会在
`MessageStoreTests.AllLanguages_ShareSameKeys` 里失败（这是有意的）。

**加一种语言**：

1. 在每个类别目录下各加一份 `<culture>.json`（键必须齐全）；
2. 如果要在游戏内可切换，在 `src/Application.Shared/Languages/LanguageEnum.cs` 加枚举值，
   并在 `SupportedCultureManager` 的映射里加上 `CultureInfo`。

**加一个类别**：

1. 在**要使用它的项目**里新建 `i18n/NewCategory/`，放入各语言 JSON——
   宿主用的放 `Application.Resources`，只有插件用的放插件项目；
2. （可选）`MessageCategories` 加一个常量，方便调用方拼写安全地引用；
3. 重新编译即可——生成器会产出 `NewCategory` 常量类。

> 类别文件不必和 `MessageCategories` 在同一个程序集。`ScriptMessage` 就是这样：
> 常量类和类别名都在 `Application.Plugin.Script`（`ScriptMessageCategories.ScriptMessage`），
> `MessageCategories` 只登记宿主自己的 `ClientMessage`。
>
> Core 也不认识插件类别：它只提供 `IClientCulture.GetMessageByCategory(category, key, ...)`
> 和 `NPCConversationManager.GetMessageByCategory(...)` 这类通用入口，类别名由调用方传入。
> 插件侧用 `ScriptMessageExtensions.GetTalkMessage(this, key, ...)`（必须带接收者调用，
> 扩展方法不参与无接收者的成员查找）。

**给插件加文案**：

1. 在插件项目里建 `i18n/NewCategory/zh-CN.json`（和 `en-US.json`）；
2. csproj 里引入 `MessageSource.props`（见 §3），并在 `CopyToPlugins` 目标里把 JSON 拷到
   `Plugins/{插件名}/i18n/`（照 `Application.Plugin.TreasureMap.csproj` 抄）；
3. 插件运行时 `PluginContainer` 会自动注册该目录，不需要额外代码。

**插件目录布局**（运维）：把整个 `{插件名}` 目录放进 `Plugins/` 即可，**不要**只丢一个 dll。
`PluginManager` 的加载单位是目录：`LoadPlugin("{插件名}")`。

## 6. 使用方式

```csharp
// 按玩家语言取并格式化（channel 侧）
client.CurrentCulture.GetMessageByKey(nameof(ClientMessage.Ban_NoticePlayer), operatorName);
client.CurrentCulture.GetMessageByCategory(ScriptMessageCategories.ScriptMessage, nameof(ScriptMessage.KerningPQ_Intro));

// NPC 脚本内部：插件扩展方法，固定 ScriptMessage 类别（必须带接收者）
this.GetTalkMessage(nameof(ScriptMessage.KerningPQ_Intro));

// 与玩家语言无关（服务端日志、GM 广播）
ClientMessage.GetDefault(nameof(ClientMessage.Server_Start));
ClientMessage.FormatDefault(nameof(ClientMessage.Server_StartSuccess), "成功", port);

// 直接用常量查表
MessageStore.Get(MessageCategories.ClientMessage, ClientMessage.BanReason, CultureInfo);

// 插件自己的文案（生成器固定输出到 Application.Resources.Messages 命名空间，与目录名无关）
TreasureMapText.Format(TreasureMapText.LevelTooLow, clientCulture);
```

找不到键时 `Get` 返回 `null`，`Format` 返回键名本身，并记一条 Verbose 日志 `i18n未找到{Key}`。
